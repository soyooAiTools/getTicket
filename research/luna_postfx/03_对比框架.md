# 对比框架

## 路线 A：打包前，走 Luna 官方支持路径

| 路径 | 能力 | 风险 | 适合效果 |
|---|---|---|---|
| Post Effects | 官方支持，能持久化到构建 | 只支持 SSAO | SSAO |
| CSS Filters | 官方平台支持 | 只能做全局色彩类效果 | 亮度、对比度、饱和度、灰度、复古、色相 |
| Render Objects | 官方支持，自 7.1.0 起可用 | 不是完整 post stack | Outline、Silhouette、X-Ray、材质替换 |
| External JS + Bridge | 官方支持 | 需要自建 JS 方案 | 暗角、噪点、扫描线、色彩遮罩、轻度 blur |

## 路线 B：打包前，把后处理改写为“伪后处理”

| 方式 | 本质 | 适合效果 | 风险 |
|---|---|---|---|
| 材质/Shader 改写 | 把屏幕后处理转成对象级效果 | Glow、边缘高亮、局部扭曲 | 维护成本上升 |
| UI Overlay / 全屏贴图 | 用 UI 或贴图叠层模拟 | Vignette、Film Grain、Color Wash | 效果受分辨率影响 |
| 粒子 / Sprite Halo | 用发光精灵模拟 Bloom | Bloom / Glow | 美术配合较多 |
| Render Objects | 额外渲染通道 | Outline / X-Ray | 额外 pass 带来性能成本 |

## 路线 C：打包后，直接改 HTML 产物

| 方式 | 能力 | 适合效果 | 风险 |
|---|---|---|---|
| 给 `#application-canvas` 加 CSS filter | 成本最低 | 色调、对比、饱和度、灰度、色相 | 全局统一，不能分层 |
| 在 canvas 上方加 DOM Overlay | 中等灵活 | Vignette、Noise、Scanline、Color Overlay | 需要兼容广告平台容器 |
| 额外 JS 控制动画参数 | 可动态切换风格 | 过场变色、命中闪白、低血量红晕 | 需要自己维护状态同步 |
| 深改 Luna runtime | 理论上最强 | 理论上更多 | 极高风险，不建议 |

## 不推荐路线

| 路线 | 原因 |
|---|---|
| 直接搬 Unity 原生 URP Volume 栈 | 官方明确 `Post Processing = No` |
| 继续依赖旧 Post Processing package | 官方 common issues 已提示会触发构建问题 |
| 在最终产物里反向修改 Luna 核心运行时 | 版本脆弱、排障成本高、广告侧兼容差 |
