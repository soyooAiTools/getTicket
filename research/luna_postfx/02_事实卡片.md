# 事实卡片

## F1 [官方] Luna 的 URP 不支持完整 Post Processing
- 证据：官方 URP 支持页明确写明 `Post Processing: No`
- 含义：不能把 Unity 原生 URP Volume 栈当作 Luna 可直接复用能力
- 可信度：高

## F2 [官方] Luna 7.1.0 官方承认的 Post Effects 只有两类
- 证据：官方 Post Effects 页写明：
  - 支持自 `7.1.0`
  - 只在 `WebGL 2`
  - 支持效果只有：
    - `SSAO`
    - `CSS filters`
- 含义：官方并没有开放 Bloom / DOF / Motion Blur / Chromatic Aberration / Lens Distortion 等完整后处理栈
- 可信度：高

## F3 [官方] Dev Environment 的 Post effects 配置会持久化到导出构建
- 证据：Dev Environment 页面写明 Post effects section 中的配置会在构建后保留到 exported build bundle
- 含义：如果采用官方支持的 Post effects 能力，打包前配置是有效路径
- 可信度：高

## F4 [官方] Dev Environment 不支持 Filter Settings section
- 证据：Dev Environment 页面把 `Filter Settings section` 列入不支持项
- 含义：CSS Filters 更偏向平台编辑能力，不是本地 Dev Environment 的主能力
- 可信度：高

## F5 [官方] 平台编辑器支持的 CSS Filters 只有 6 项
- 证据：CSS Filters 页面列出：
  - Brightness
  - Saturate
  - Contrast
  - Sepia
  - Grayscale
  - Hue Rotate
- 含义：全局颜色风格、伪 LUT、冷暖调、黑白、老照片风是可以做的
- 可信度：高

## F6 [官方] Render Objects 7.1.0 起支持，可用于 outline / x-ray / silhouette
- 证据：Render Objects 页面明确写出该功能自 7.1.0 起支持，并列出典型用途
- 含义：很多“像后处理”的视觉效果，其实可以转为 Render Objects 替代方案
- 可信度：高

## F7 [官方] Render Objects 的渲染事件支持并不完整
- 证据：Render Objects 页明确说明不支持 `BeforeRenderingPostProcessing` 和 `AfterRenderingPostProcessing`
- 含义：它能做很多“附加渲染通道”效果，但不能替代完整的后处理执行链
- 可信度：高

## F8 [官方] 旧的 Unity Post Processing package 在 Luna 中会导致构建风险
- 证据：Common Issues 页面明确说构建失败可能由 Post Processing package 引起，并建议移除
- 含义：旧版 PPS v2 不是可靠路线
- 可信度：高

## F9 [官方] Luna 支持运行时插入自定义 JS
- 证据：Insert JS at Runtime 页面明确给出 `Bridge.Script.Write()` 示例
- 含义：打包前即可把 DOM / CSS / JS 层增强作为官方支持路线接进工程
- 可信度：高

## F10 [官方] Luna 支持引入外部 JS 文件
- 证据：External JS Libraries 页面明确说明可以直接在插件中引入第三方 JS 文件
- 含义：我们可以把自己的 `luna-postfx.js` 作为外部库纳入，而不是每次手改产物
- 可信度：高

## F11 [本地插件] 7.1.0 配置中唯一显式的 postprocess 配置是 SSAO
- 证据：`config.json` 的 `postprocesses` 节点只有 `ssao`
- 含义：插件本地证据与官方文档一致，未见 Bloom / Vignette / DOF 等原生映射
- 可信度：高

## F12 [本地插件] 7.1.0 release notes 仅提到 URP Render Objects 与 SSAO warning
- 证据：本地 `release-notes.json`
- 含义：7.1.0 的新增重点不是开放完整后处理，而是补了 Render Objects 与 SSAO 相关能力
- 可信度：高

## F13 [本地模板] Luna 标准 HTML 模板里内建了 canvas filter 逻辑
- 证据：
  - `body.pug` 包含 `canvas#application-canvas`
  - `body.pug` include 了 `filters.pug`
  - `filters.pug` 直接对 `#application-canvas` 执行 `element.style.filter = ...`
- 含义：Luna 内部确实预留过基于 CSS Filter 的产物层能力
- 可信度：高

## F14 [本地模板] 模板滤镜支持项与官方 CSS Filters 一致
- 证据：`filters.pug` 中默认值为：
  - grayscale
  - sepia
  - hue-rotate
  - contrast
  - brightness
  - saturate
- 含义：官方平台上的 CSS Filters 和模板内实现是一致的同一类能力
- 可信度：高

## F15 [样本产物] 用户提供的最终 HTML 保留了稳定 canvas 挂点
- 证据：`E:\Download\打包后文件.html` 中存在 `canvas id="application-canvas"`，启动时也明确把它传给 `new LunaUnity.Application(...)`
- 含义：打包后仍可通过 DOM 注入对最终渲染层做二次增强
- 可信度：高

## F16 [样本产物] 用户样本中没有直接检出模板滤镜关键字
- 证据：在最终 HTML 中没有搜到 `playgroundFiltersOverrides`、`luna:filters:update` 等模板关键字
- 含义：模板预留能力不一定会原样出现在最终产物中，所以产物层方案应以“显式注入自定义脚本”为主，而不是赌内部钩子还在
- 可信度：中高

## F17 [标准文档] CSS filter 可以直接施加到 canvas 元素，支持 blur / contrast / hue-rotate 等
- 证据：MDN `filter` 文档
- 含义：打包后通过 HTML/CSS 增加全局视觉处理在 Web 平台上是可行的
- 可信度：高

## F18 [官方] GPU Instancing 所属的 Optimized graphics API 不支持
- 证据：官方 Supported Rendering Features 页面把 `Optimized graphics API (instancing, cbuffers, vertexBuffer partial update)` 列入 Not Supported
- 含义：Unity 里依赖 GPU Instancing 的那条优化路径，不能直接指望在 Luna 中等价生效
- 可信度：高

## F19 [官方] Playworks 支持 Dynamic Batching
- 证据：官方 Dynamic Batching 页面明确标注支持 `2D / 3D / BIRP / URP`
- 含义：大量重复物体的合批优化，在 Luna 里应优先考虑 Dynamic Batching，而不是 GPU Instancing
- 可信度：高

## F20 [官方] Playworks 支持 Static Batching
- 证据：官方 Static Batching 页面明确标注 `BIRP ✅ / URP ✅ / Runtime static batch ✅`
- 含义：静态场景物体可以通过 Static Batching 获得 draw call 优化
- 可信度：高

## F21 [官方] 历史版本修复过“设备不支持 instancing”错误
- 证据：官方 Release Notes 3.7.0 写明 `Fixed errors when a device does not support instancing`
- 含义：这更像是兼容性修复，不代表 Luna 正式支持 GPU Instancing；反而说明设备侧不应依赖这项能力
- 可信度：中高
